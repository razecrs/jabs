# Memory, Stability & Boot: Minecraft 1.7.10 Dedicated Server (JABS Native GC vs. HotSpot)

**Result:** On identical worlds and default `-Xmx2G` JVM heap settings (no `-Xms` floor), JABS native `server.exe` (commit `eb1a070`) uses **2.74–2.78x less Working Set** and **4.95–4.98x less Private RAM** than Vanilla `1.7.10-server.jar` on JDK 25, with **no memory growth across a sustained 10-minute 1-player run** (`137.9 MB` at 60 s to `134.6 MB` at 600 s, `0` tick overload warnings). On apples-to-apples startup and world generation, however, HotSpot C2 is still faster than JABS (`3.39s` vs. `5.79s` warm; `5.79s` vs. `16.38s` cold fresh worldgen), since JABS compiles shards separately without cross-TU LTO and keeps loop-backedge safepoint polls unhoisted.

## Fair comparison (commit `eb1a070` vs. JDK 25 `-Xmx2G -XX:+UseG1GC`)

Both engines were driven by [`tools/bench_1_7_10_server.py`](../../tools/bench_1_7_10_server.py) in clean directories:
- **Scenario A (Cold + fresh worldgen):** empty directories with `level-seed=42`.
- **Scenario B (Warm + 10 min 1-player):** identical copies of the Scenario A `world/` directory, followed by a 600 s 1-player session (`benchbot`) receiving `0x26 MapChunkBulk` packets and answering keepalives.

| Scenario & Metric | Vanilla `1.7.10` JVM (`-Xmx2G -XX:+UseG1GC`, no `-Xms`) | JABS Native (`server.exe`, `eb1a070`) | Ratio |
|---|---:|---:|---:|
| **Cold boot + `seed=42` worldgen** | **`5.79s`** (`Done (3.359s)!`) | `16.38s` (`Done (13.799s)!`) | JVM `2.83x` faster |
| **Cold idle Working Set** | `460.8 MB` | **`165.7 MB`** | **JABS `2.78x` smaller** |
| **Cold idle Private RAM** | `646.3 MB` | **`130.5 MB`** | **JABS `4.95x` smaller** |
| **Warm boot (identical `world/`)** | **`3.39s`** (`Done (0.780s)!`) | `5.79s` (`Done (3.275s)!`) | JVM `1.71x` faster |
| **Warm idle Working Set** | `372.2 MB` | **`183.8 MB`** | **JABS `2.02x` smaller** |
| **Warm idle Private RAM** | `653.4 MB` | **`147.3 MB`** | **JABS `4.44x` smaller** |
| **600 s 1-player end Working Set** | `476.8 MB` | **`173.7 MB`** | **JABS `2.74x` smaller** |
| **600 s 1-player end Private RAM** | `670.6 MB` | **`134.6 MB`** | **JABS `4.98x` smaller** |
| **Overload warnings / Zlib fails** | `0` / `0` (`85` bulk pkts) | `0` / `0` (`88` bulk pkts) | Parity |

*Before the Immix + LOS GC was added, the same `1.7.10` server leaked uncollected `malloc`/`calloc` allocations at `~6 MB/s` (observed reaching `8,453.5 MB` Private RAM).*

## Environment, reproducibility & caveats

| | |
|---|---|
| JABS runtime commit | `eb1a070` (`server.exe` built with `--opt 2`, Clang/LLD, `120,539,648` bytes) |
| Benchmark script | [`tools/bench_1_7_10_server.py`](../../tools/bench_1_7_10_server.py) (Mojang-free; requires local `1.7.10-server.jar` and built `server.exe`) |
| CPU / RAM / OS | Intel Core i7-9750H @ 2.60GHz, 31.9 GB RAM, Windows 11 Home 10.0.26300 |
| JVM baseline | Microsoft OpenJDK 25.0.4.101 (`-Xmx2G -XX:+UseG1GC`, no `-Xms`) |
| Caveats | Single pair of runs; 1 stationary bot player (`benchbot` sending keepalives and receiving initial spawn chunks); multi-player exploration, heavy entity churn, and client rendering are untested here |
